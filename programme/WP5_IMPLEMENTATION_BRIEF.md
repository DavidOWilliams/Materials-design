## Milestones and evidence
1. **Contract inventory and UI skeleton**: document callable service signatures, typed Brief/assumptions/RunInputs, supported architectures, errors, persistence and replay. Implement UI navigation and a validated editable brief (duty, geometry, boundaries, constraints, objectives, budget) without silently defaulting unsupported fields. Test valid edits, invalid units, unknown material/property, zero/negative budget. Evidence: contract map, validation tests, UI captures, source SHA. Done when saved brief round-trips exactly and invalid edits fail closed.
2. **Execute and inspect**: UI launches a bounded campaign through core service; show homogeneous reference and supported layered/gradient alternatives, generated revisions, progress, numerical eligibility and Pareto/objective units. Test altered brief, budget exhaustion, no-feasible solution, nonfinite output and unsupported architecture. Evidence: typed input, immutable dossier, execution log, tests. Done when UI-run matches direct core output for same hashes.
3. **Compare and edit assumptions**: display intended vs estimated achieved geometry/composition and pre/post objectives; permit versioned process scenario/assumption edits, run fresh evaluations, prevent stale cached results. Separate numerical completion, qualification, hard constraints, conditional manufacturing feasibility and evidence maturity. Reject incompatible brief/duty/solver/property comparisons; unknown never pass. Evidence: paired dossiers, invalid-comparison and stale-cache tests. Done when changed assumption changes identity and downstream result or honestly records no effect.
4. **Cancel, recover, reopen**: cooperative cancellation at supported evaluation boundaries; durable manifest, journal and attempts sidecar; resume/reopen with identity validation. Test checkpoint-write before/after failure, corrupt or missing sidecar, repeated resume, alternate duty, interrupted run. Do not promise mid-solver restart. Evidence: evaluator-call audit, before/after journals and negative tests. Done when actual numerical work is correctly accounted and no false success is shown.
5. **Export and replay**: user downloads portable dossier with intended hash, estimated state, provenance, assumption versions, objective conditions, unknown measured state and explicit limitations; UI imports/reopens and triggers separate numerical recomputation where supported. Reject forged measured evidence and incompatible schemas. Evidence: export, clean-process replay, hash verification, screenshots and README. Done when David can complete full workflow without code edits.
## Gates
G1: end-to-end UI→core→persist→reopen→replay across valid fixtures, with commands/logs and frozen SHA.
G2: valid variants, invalid/unsupported, unknown, cancellation, recovery, stale cache, incompatible comparisons and no-feasible cases.
G3: independently tasked reviewer checks frozen source/evidence, numerical references, architecture and claims; findings closed by a subsequent review. No self-approval.
## Boundaries
Use open licensed existing tools and methods. No new scientific physics, ML training, CFD/sintering/full residual-stress prediction or legacy keyword-score conversion. Preserve D1 vs V1. UI must not import into numerical core. Avoid unrequested redesign. Include runnable validation commands established from actual environment (likely foundation/setup.sh, pytest foundation/tests and relevant workflow commands; verify before asserting).
