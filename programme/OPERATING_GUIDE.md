## Restricted-shell network recovery and verification — WP5 precedent (26 October 2026)

**Observed problem.** In the WP5 execution container, `git ls-remote https://github.com/DavidOWilliams/Materials-design.git HEAD` failed with `Could not resolve host: github.com`. Python HTTPS requests to `github.com` and `api.github.com` and DNS resolution of `pypi.org` also failed; a direct TCP attempt to GitHub port 443 was refused. This supports a local environment DNS/outbound-network restriction, **not** a proven Git authentication problem. The GitHub connector independently succeeded in fetching files, creating commits and opening PRs. Connector access does not imply shell networking. Avoid repeating an unchanged failed clone.

**Preferred repeatable route for WP6/WP7.**
1. Verify exact branch, tested parent SHA and current implementation HEAD through the GitHub integration; compare commits and inspect applicable `AGENTS.md`, foundation setup/lockfile, service contracts, tests and workflows. Never silently use a different checkout or move acceptance/preservation refs.
2. Try an existing local checkout/cache, then supported archive retrieval, then GitHub tree/blob retrieval and content-identity checks where available. Reconstruct only if all required source, tests, fixtures, configs and lockfiles can be retrieved and completeness verified. Individual file reads alone are **not** a verified complete checkout.
3. If local network or dependency installation is restricted, use an isolated branch-scoped GitHub Actions workflow with `actions/checkout`, a recorded `git rev-parse HEAD` and `HEAD^{tree}`, a check against `GITHUB_SHA`, Python 3.12 and the declared `foundation/requirements.lock.txt` with `pip install --require-hashes` and `pip check`.
4. Run focused work-package tests plus `PYTHONPATH=foundation python -m pytest -q foundation/tests`; extend with end-to-end application and negative challenge tests as implemented. Capture commands, exit codes, source SHA, dependency inventory, logs and dossiers as downloadable Actions artifacts even on test failure. Do not mark a test as passed from workflow configuration alone.
5. Retrieve actual Actions run/job conclusions and artifacts, fix failures, rerun at a documented SHA, and distinguish CI functional checks from separate interactive UI/browser inspection. Freeze an exact tested SHA and evidence package before independent Gate 3 review. Do not self-approve Gate 3.
